## 제1절 실험환경 및 데이터셋 구성

### (1) 실험환경

본 연구의 실험환경은 다음과 같이 구성하였다.

| 항목 | 구성 |
|------|------|
| 블록체인 네트워크 | Ethereum Mainnet Fork (Hardhat, chainId 31337) |
| 노드 연결 | Alchemy RPC를 통한 메인넷 상태 포크 |
| 스마트 컨트랙트 | Solidity 0.5.17 ~ 0.8.27, OpenZeppelin Contracts v5.4.0 |
| 프레임워크 | Hardhat v2.22.2, ethers.js v6.16.0 |
| 탐지 시스템 | Python 3.11, Streamlit 기반 실험 대시보드 |
| 랜덤 시드 | 2026 (재현 가능) |

스마트 컨트랙트는 Macro/Micro 분리 토큰(`FDSMacroToken.sol`, `FDSMicroToken.sol`), 통합 스테이블코인(`FDSStablecoin.sol`), 서킷 브레이커(`CircuitBreaker.sol`), 그리고 Mock 인프라(`MockDEX`, `MockOracle`, `MockVault`)로 구성하였다. 컴파일러는 Solidity 0.5.17부터 0.8.27까지 9개 버전을 병렬 지원하며, 옵티마이저(runs=200)를 활성화하여 가스 효율을 확보하였다.

### (2) 데이터셋 구성

본 연구에서는 두 가지 데이터 소스를 결합한 하이브리드 데이터셋을 구성하였다.

가. 시뮬레이션 데이터셋

`BenchmarkDataGenerator` 클래스를 통해 최대 100,000개의 시나리오를 자동 생성하며 재현성을 위한 시드 기반 난수 생성을 적용하였다. 시나리오는 공격 8종과 정상 6종으로 구분된다.

| 구분 | 시나리오 유형 |
|------|-------------|
| 공격 (8종) | Infinite Mint, Reserve Drain, Flash Loan Depeg, Sybil Attack, Threshold Evasion, Gradual Escalation, Camouflage, Sandwich Attack |
| 정상 (6종) | Normal Transfer, Large Transfer, Liquidity Add, Batch Payment, Normal Mint, Normal Flash Loan |

공격 비율은 1%~20% 범위에서 설정 가능하며, 네트워크 상태는 Normal, Congested, Severe의 세 조건을 혼합하여 실제 블록체인 환경의 변동성을 반영하였다.

나. 실제 트랜잭션 데이터셋

이더리움 메인넷 2024년 7월 28일 블록에서 수집한 실제 트랜잭션 3,126건을 DeFiTail 데이터셋 형식으로 활용하였다. 각 트랜잭션은 JSON 형식으로 저장되어 있으며, `tokenFlows` 필드의 `tags` 배열과 `summary.types` 필드에서 Sandwich/PartialSandwich 공격 여부를 판별하여 Ground Truth 레이블(`ATTACK`/`NORMAL`)을 자동 부여하였다. 수익(`profit`) 필드를 기반으로 거래 금액을 산출하며, 수익 정보가 없는 경우 기본값 500,000을 적용하였다.

다. State Mocking

HoustonLite 엔진(Engine 3)의 불변량 기반 검사를 위해 모든 시나리오에 `state_before`/`state_after` 딕셔너리를 동적으로 주입하였다. 
기준 상태는 `initial_supply=10,000,000`, `current_supply=15,000,000`, `reserve=2,000,000`, `price=1.0`, `collateral=current_supply × 1.20`으로 설정하였으며, 시나리오 유형별 상태 변화는 다음과 같다.

| 시나리오 유형 | `state_after` 변화 | 위반 Invariant |
|---|---|---|
| `INFINITE_MINT` | `totalSupply` 증가, `collateral` 불변, `price` 하락 | INV-1, 7, 8 |
| `RESERVE_DRAIN` | `reserve` 소진, `collateral` 50% 감소 | INV-3, 4 |
| `FLASH_LOAN_DEPEG` | `price` 급락 (8~35%) | INV-6 |
| `NORMAL_MINT` | `totalSupply` + `collateral` 비례 증가 (담보 105%) | 없음 (정상) |
| `NORMAL_TRANSFER` | 상태 변화 없음 | 없음 (정상) |

### (3) 비교 대상 시스템

본 연구는 제안하는 FDS 2계층 앙상블 시스템의 성능을 객관적으로 평가하기 위해 다음 6개 시스템을 비교 분석하였다.

| 시스템명 | 구현 클래스 | 탐지 방식 | 대응 방식 |
|---------|------------|-----------|----------|
| 수동 거버넌스 (Baseline) | `ManualGovernanceSystem` | 4단계 인간 워크플로우 (알림→판단→실행→복구) | `pause_all` |
| FDS 앙상블 + 1계층 | `FDSSingleLayerSystem` | 피처 기반 이상 점수 + 과부하 연동 | `pause_all` |
| FDS 앙상블 + 2계층 (제안 모델) | `FDSTwoLayerSystem` | Macro/Micro 분리 + 3엔진 앙상블 | 선택적 차단 |
| Engine 1 단독 + 1계층 | `FDSEngine1System` | AnomalyScorer 100% 반영 | `pause_all` |
| Engine 2 단독 + 1계층 | `FDSEngine2System` | 임계값 규칙 + 공격 패턴 매칭 | `pause_all` |
| Engine 3 단독 + 1계층 | `FDSEngine3System` | HoustonLite 불변량 검사 | `pause_all` |
